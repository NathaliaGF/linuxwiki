Módulo 09

Shell Scripting

Automatize tarefas repetitivas, crie scripts de backup, monitoramento e setup de servidores. Aprenda a escrever scripts Bash robustos com tratamento de erros, funções reutilizáveis e as boas práticas que separam um script frágil de um script confiável.

Shebang e estrutura básica

📖 Explicação

O shebang (#!) na primeira linha diz ao kernel qual interpretador usar para executar o script. Sem ele, o kernel tenta usar o shell atual — comportamento imprevisível.

  • #!/bin/bash: usa o bash em /bin/bash. Funciona na maioria dos sistemas Linux.
  • #!/usr/bin/env bash: mais portável — usa o bash que estiver no $PATH. Útil quando o bash pode estar em locais diferentes (macOS, alguns servidores).

Boas práticas iniciais: adicione set -euo pipefail logo após o shebang — essa linha previne uma classe inteira de erros silenciosos.

🔍 Exemplo Concreto 
#!/usr/bin/env bash
set -euo pipefail

# set -e  : encerra o script se qualquer comando retornar erro
# set -u  : trata variáveis não definidas como erro
# set -o pipefail : propaga erros em pipes

echo "Iniciando script..."

# Tornando executável e executando:
chmod +x meu-script.sh
./meu-script.sh          # ./ é necessário porque . geralmente não está no $PATH
⚠️ Erros comuns
  • Esquecer o shebang: o script pode funcionar no terminal (que já é bash) mas falhar quando chamado por cron ou outro processo.
  • Não usar set -e: sem ele, o script continua rodando depois de um erro e pode fazer dano em estado inconsistente.
  • Tentar rodar com bash script.sh sem chmod +x: funciona, mas é boa prática tornar explícito.

Variáveis, strings e substituição

📖 Explicação

Variáveis em bash não têm tipo — tudo é string. Use ${} para delimitar o nome da variável quando necessário, e sempre coloque aspas duplas ao usar variáveis para evitar word splitting e glob expansion.

🔍 Exemplo Concreto 
#!/bin/bash
set -euo pipefail

# Declaração (sem espaços em torno do =)
nome="João"
contador=0

# Uso — sempre com aspas para evitar word splitting
echo "Olá, $nome"
echo "Olá, ${nome}!"    # chaves para delimitar nome de variável

# Substituição de comando ($() é moderno; `backtick` é legado)
data=$(date +%Y-%m-%d)
arquivos=$(ls -1 | wc -l)

# String operations
texto="hello world"
echo ${#texto}           # comprimento: 11
echo ${texto^^}          # maiúsculo: HELLO WORLD
echo ${texto^}           # primeira letra maiúscula: Hello world
echo ${texto/hello/oi}   # substituição: oi world

# Valor padrão / verificação
echo ${VAR:-"padrão"}    # usa "padrão" se VAR não definida (não altera VAR)
echo ${VAR:="padrão"}    # usa "padrão" E define VAR se não definida
echo ${VAR:?"VAR é obrigatória"}  # encerra com erro se não definida
⚠️ Erros comuns
  • Espaços ao redor do =: nome = "João" causa erro. Bash interpreta como comando nome com argumentos = e "João".
  • Não usar aspas: arquivo="meu arquivo.txt" e depois rm $arquivo tenta remover dois arquivos (meu e arquivo.txt). Use sempre rm "$arquivo".
  • Confundir $() com $(()): $() é substituição de comando; $(()) é aritmética inteira: echo $((2 + 3)).

Condicionais: if, elif, else, case

📖 Explicação

Bash tem duas formas de teste: [ ] (comando test, POSIX) e [[ ]] (keyword bash, mais seguro). Prefira [[ ]] em scripts bash — não faz word splitting nos argumentos e suporta regex com =~.

🔍 Exemplo Concreto 
# if com [[ ]] (recomendado em bash)
if [[ "$1" = "admin" ]]; then
    echo "Bem-vindo, admin"
elif [[ "$1" = "user" ]]; then
    echo "Bem-vindo, usuário"
else
    echo "Não reconhecido"
fi

# Operadores de arquivo
[[ -f arquivo ]]   # existe e é arquivo regular
[[ -d dir     ]]   # existe e é diretório
[[ -r arquivo ]]   # tem permissão de leitura
[[ -w arquivo ]]   # tem permissão de escrita
[[ -x arquivo ]]   # tem permissão de execução
[[ -z string  ]]   # string está vazia
[[ -n string  ]]   # string não está vazia

# Operadores numéricos
[[ $a -eq $b ]]    # equal
[[ $a -ne $b ]]    # not equal
[[ $a -lt $b ]]    # less than
(( a > 5 ))        # aritmética diretamente — mais legível para números

# case — mais limpo que múltiplos elif
case "$distro" in
    ubuntu|debian)  echo "APT" ;;
    fedora|rhel)    echo "DNF" ;;
    arch)           echo "pacman" ;;
    *)              echo "Desconhecida" ;;
esac
💡 Analogia — [[ ]] vs [ ]

Pense em [ ] como uma calculadora básica dos anos 80 — funciona, mas tem casos de borda bizarros (tente [ $var = "" ] com var indefinida sem aspas). [[ ]] é a calculadora moderna que trata os casos estranhos automaticamente. Ao escrever scripts bash, sempre use [[ ]].

Loops: for, while, until

🔍 Exemplo Concreto 
# for em lista explícita
for fruta in maçã banana laranja; do
    echo "Fruta: $fruta"
done

# for em arquivos (glob expansion)
for arquivo in /var/log/*.log; do
    echo "Tamanho: $(wc -c < "$arquivo") bytes — $arquivo"
done

# for range C-style
for (( i=1; i<=10; i++ )); do
    echo $i
done

# while — executa enquanto condição for verdadeira
contador=0
while [[ $contador -lt 5 ]]; do
    echo "Contador: $contador"
    (( contador++ ))
done

# Ler arquivo linha por linha (forma correta)
while IFS= read -r linha; do
    echo "Linha: $linha"
done < /etc/hosts

# until — executa ATÉ a condição ser verdadeira
until ping -c1 google.com &>/dev/null; do
    echo "Aguardando conectividade..."
    sleep 5
done
echo "Conectado!"
⚠️ Erros comuns
  • for linha in $(cat arquivo): itera sobre palavras, não linhas. Use o padrão while IFS= read -r linha; do ... done < arquivo.
  • Esquecer IFS= no read: sem IFS=, espaços no início e fim da linha são removidos. Sem -r, barras invertidas são interpretadas.
  • Loop infinito por engano: sempre verifique que a condição do while pode se tornar falsa. Adicione um contador de segurança se necessário.

Funções e argumentos

📖 Explicação

Funções em bash reutilizam código e organizam scripts complexos. Declare todas as variáveis internas com local para evitar contaminar o escopo global.

Argumentos de funções: $1, $2, ... $@ = todos os argumentos (separados), $# = quantidade de argumentos, $* = todos como uma string.

🔍 Exemplo Concreto 
# Funções de log — padrão comum em scripts
log_info() {
    echo "[INFO] $(date '+%H:%M:%S') $*"
}

log_error() {
    echo "[ERROR] $(date '+%H:%M:%S') $*" >&2   # stderr
}

verificar_root() {
    if [[ $EUID -ne 0 ]]; then
        log_error "Este script requer privilégios de root"
        exit 1
    fi
}

# Argumentos: use "$@" para preservar argumentos com espaços
calcular_media() {
    local soma=0
    local count=$#
    for n in "$@"; do
        (( soma += n ))
    done
    echo $(( soma / count ))
}

media=$(calcular_media 10 20 30 40)
log_info "Média: $media"

# Retornar valor via echo (capturar com $())
obter_distro() {
    if [[ -f /etc/os-release ]]; then
        source /etc/os-release
        echo "$ID"
    else
        echo "unknown"
    fi
}

distro=$(obter_distro)
log_info "Distro: $distro"
⚠️ Erros comuns
  • Esquecer local: variáveis sem local são globais e podem sobrescrever variáveis do script principal.
  • Usar return para retornar strings: return só retorna números (exit code 0-255). Para retornar strings, use echo e capture com $().
  • Usar $* ao invés de "$@": "$*" junta tudo em uma string; "$@" preserva argumentos individuais. Use sempre "$@" para iterar.

Exit codes e tratamento de erros

📖 Explicação

Todo comando Unix retorna um exit code: 0 = sucesso, qualquer outro valor = erro. A variável $? contém o exit code do último comando. Com set -e, qualquer exit code não-zero encerra o script.

🔍 Exemplo Concreto 
# Verificando exit code
ls /etc/passwd
echo "Exit code: $?"      # 0 (sucesso)

ls /naoexiste
echo "Exit code: $?"      # 2 (arquivo não encontrado)

# Tratamento de erro — prefira if ! ao invés de verificar $?
if ! cp origem destino 2>/dev/null; then
    log_error "Falha ao copiar arquivo"
    exit 1
fi

# Valores comuns de exit code
# 0   = sucesso
# 1   = erro geral
# 2   = uso incorreto do shell/comando
# 126 = arquivo não executável
# 127 = comando não encontrado
# 130 = Ctrl+C (SIGINT)

# set -e com || true — desabilita para um comando específico
rm -rf /tmp/cache 2>/dev/null || true   # falha é aceitável aqui

# Trap — executa código ao sair ou receber sinal
cleanup() {
    rm -f /tmp/arquivo_temporario
    log_info "Limpeza realizada"
}
trap cleanup EXIT          # executa cleanup() ao sair (sucesso ou erro)
trap 'log_error "Interrompido"; exit 130' INT TERM
ℹ️ Saiba mais

trap é uma das ferramentas mais poderosas para scripts robustos. trap cleanup EXIT garante que recursos temporários (arquivos, locks, containers) sejam liberados mesmo que o script seja interrompido por erro ou Ctrl+C. É o equivalente do bloco finally em outras linguagens.

Scripts reais: backup, monitor, setup

📖 Explicação

Os três scripts abaixo aplicam todos os conceitos anteriores em casos de uso reais. Analise cada um prestando atenção em: tratamento de erros, uso de variáveis com defaults, funções de log e limpeza de arquivos antigos.

🔍 Script 1 — backup.sh 
#!/bin/bash
set -euo pipefail

# Configuração com valores default
ORIGEM="${1:-$HOME}"
DESTINO="${2:-/backup}"
DATA=$(date +%Y-%m-%d_%H-%M-%S)
ARQUIVO="backup_${DATA}.tar.gz"

log() { echo "[$(date '+%H:%M:%S')] $*"; }

# Verificações antes de começar
[[ -d "$ORIGEM" ]] || { echo "Origem não existe: $ORIGEM"; exit 1; }
mkdir -p "$DESTINO"

log "Iniciando backup de $ORIGEM"
log "Destino: $DESTINO/$ARQUIVO"

# Criar backup excluindo arquivos temporários
tar -czf "$DESTINO/$ARQUIVO" --exclude='*.tmp' --exclude='.cache' "$ORIGEM"

TAMANHO=$(du -sh "$DESTINO/$ARQUIVO" | cut -f1)
log "Backup concluído: $ARQUIVO ($TAMANHO)"

# Manter apenas os últimos 7 backups (rotação automática)
cd "$DESTINO"
ls -t backup_*.tar.gz | tail -n +8 | xargs -r rm --
log "Backups antigos removidos. Total atual: $(ls backup_*.tar.gz | wc -l)"
🔍 Script 2 — monitor-disco.sh 
#!/bin/bash
set -euo pipefail

LIMITE="${1:-90}"     # % de uso para alertar (default: 90)
EMAIL="${2:-root}"

# Lê saída do df linha por linha usando process substitution
while IFS= read -r linha; do
    uso=$(echo "$linha" | awk '{print $5}' | tr -d '%')
    ponto=$(echo "$linha" | awk '{print $6}')

    if (( uso >= LIMITE )); then
        mensagem="ALERTA: Disco $ponto está em ${uso}% (limite: ${LIMITE}%)"
        echo "$mensagem"
        # Tenta enviar email, ignora erro se mail não disponível
        echo "$mensagem" | mail -s "Alerta disco - $(hostname)" "$EMAIL" 2>/dev/null || true
    fi
done < <(df -h | tail -n +2 | grep -v tmpfs)
🔍 Script 3 — setup-servidor.sh 
#!/bin/bash
set -euo pipefail

# Verificar root antes de qualquer coisa
[[ $EUID -eq 0 ]] || { echo "Execute como root: sudo $0"; exit 1; }

# Funções de log coloridas
log() { echo -e "\033[0;32m[✓]\033[0m $*"; }
err() { echo -e "\033[0;31m[✗]\033[0m $*" >&2; exit 1; }

log "Atualizando sistema..."
apt-get update -q && apt-get upgrade -y -q

log "Instalando pacotes essenciais..."
apt-get install -y -q curl wget git vim ufw fail2ban

log "Configurando firewall..."
ufw --force reset
ufw default deny incoming
ufw default allow outgoing
ufw allow 22/tcp
ufw allow 80/tcp
ufw allow 443/tcp
ufw --force enable

log "Configurando fail2ban..."
systemctl enable --now fail2ban

log "Setup concluído em $(hostname)!"
⚡ O que você precisa guardar
  • Sempre comece com #!/usr/bin/env bash e set -euo pipefail
  • Use aspas duplas em todas as expansões de variável
  • Prefira [[ ]] ao invés de [ ] em scripts bash
  • Use local para variáveis internas de funções
  • Leia arquivos linha por linha com while IFS= read -r linha; do
  • Use trap cleanup EXIT para limpeza garantida
